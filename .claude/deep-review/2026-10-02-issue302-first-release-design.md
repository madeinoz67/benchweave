## 2. Mechanism

### 2.1 cliff.toml: anchor the tag pattern (one line, measured)

`tag_pattern = "v[0-9].*"` → `"^v[0-9].*"`. Measured effect: none on the gateway changelog (byte-identical render, §1); without it, the first `ui-html-v*` tag on main corrupts the gateway changelog's Unreleased section at the next `changelog.yml` regeneration (measured, §1). This is the mitigation the REL record pre-named ("anchor the pattern, one-line cliff.toml edit at G1e") — now with the dry-run evidence that OPEN-2 demanded. The 2×2 and the release-day composite render (§1) are the direct evidence for the marker-commit step's no-bot-commit claim: with the anchor in place the regeneration at the marker push is byte-identical — annotated or lightweight tag, marker commit in history or not. The dry run itself is re-proven by the builder (acceptance P3) and its RED arm (unanchored → leak) is the control that proves the dry run bites.

### 2.2 The publish workflow — `.github/workflows/publish-ui-html.yml` (new, this repo)

Mirrors the SDK `publish.yml` shape (proven convention), scoped to what a first release needs. Load-bearing choices:

- **Trigger:** `on: release: types: [published]` — with **no `tags:` filter**: a `tags` filter is not a valid construct under the `release` event (which supports `types` only; actionlint refuses it — "tags filter is not available for release event" — and the schema/actionlint validation in acceptance P1 keeps the invalid construct from reaching main again). The required tag-namespace element is a job-level guard instead: **every job (build/smoke/publish/verify) carries `if: startsWith(github.event.release.tag_name, 'ui-html-v')`** — the gateway repo may someday carry gateway `v*` releases, and without the guard a gateway release would fire a ui-html publish. The build job's tag-match assert (below) remains the SEMANTIC gate behind the guard. No `workflow_dispatch` in v1 (fork d). `concurrency: group: publish-ui-html`, `cancel-in-progress: false`.
- **`build` job** (ubuntu-latest): checkout pinned `ref: ${{ github.event.release.tag_name }}`, `persist-credentials: false`, `submodules: false` (ui-html needs no SDK submodule — cheaper and narrower than package.yml's recursive clone); setup-uv (v10.2.0 SHA) + python 3.13; **tag-matches-version assert** (bash + tomllib one-liner: `ui-html-v${pyproject version}` must equal the release tag — the SDK's `verify_release_tag.py` role AND semantics, inlined, no new script file: a plain `removeprefix` string compare with no PEP 440 parsing, so any normalization divergence between tag and version fails CLOSED as a mismatch rather than rounding to a match); `uv build --out-dir dist packages/ui-html` (the CI-proven member invocation); `upload-artifact` (`dist-ui-html`, `if-no-files-found: error`).
- **`smoke` job** (needs build; matrix `ubuntu-latest, macos-latest` — the package.yml pair; a pure-Python wheel is OS-invariant, no Windows leg — grounded by `.gitattributes`'s machine-wide `eol=lf` normalization, §1 — disclosed): download artifact; fresh venv OUTSIDE any checkout (`$RUNNER_TEMP`, SDK precedent); `uv pip install` the wheel; then with `python -I`: import-from-venv assert, installed version == pyproject-at-tag, installed set exactly `{benchweave-ui-html, jinja2, markupsafe}`, **the resource census** (§2.3), and `verify_vendored_assets() == []` from the installed location. Checkout at the tag (`submodules: false`) supplies the census's source side.
- **`publish` job** (needs smoke; ubuntu-latest): `permissions: id-token: write, contents: read` — **job-scoped only; the ONLY place `id-token: write` appears in this repo's workflows** (acceptance P1 asserts the count). Download artifact; `pypa/gh-action-pypi-publish@dc37677b2e1c63e2034f94d8a5b11f265b73ba33 # v1.14.2` (the SDK's verified pin; publishes sdist + wheel). No token secret anywhere; trusted publishing via OIDC.
- **`verify` job** (needs publish; ubuntu-latest; no checkout): read `https://pypi.org/pypi/benchweave-ui-html/<version>/json`; assert the version is present with wheel + sdist URLs AND **both PyPI-served digests (`.digests.sha256` of the wheel AND the sdist) equal the built artifacts' digests** — the artifact is downloaded and hashed in-job, and the sdist assert is one more line over the same payload (the SDK tap job verifies the sdist digest the same way). A read-back that only checks "version exists" cannot tell a wrong or partial upload from the right one; digest equality proves the exact bytes. The comparison is well-defined by construction (critic-verified, live experiment on `benchweave-sdk` 0.4.1): publish and verify download the SAME immutable uploaded artifact, and PyPI hashes the bytes it received (both artifact types, digests == served bytes, no repackaging) — so a false-green is arithmetically impossible and transport corruption can only false-RED into the loud STOP path of the KILL rule. The PyPI URL construction is normalization-insensitive (measured: `/pypi/numpy/2.4.0-rc1/json` → 200 with the canonical record), and an empty `tag_name` is unreachable for a published release and would red the `if:` guard anyway. A short retry loop (6 × 10 s, SDK tap-job precedent) absorbs PyPI's index lag — wall-clock bounded on the runner and false-red-only by the same digest argument; the 60 s bound is convention-inherited from the SDK's live-release experience rather than measured on a fresh first publish (honest note, non-load-bearing).

No tap job (no homebrew surface for a library wheel), no changelog job (owner fork §9b: no second committed changelog; release notes are cliff-generated by the runner at release-creation time, §2.5).

### 2.3 The wheel resource census (the deferred G1e release-review item, now decidable)

**The check:** in the isolated venv (both in package.yml's existing ui-html step and the publish smoke job), byte-compare the INSTALLED package tree against the checkout tree:

```python
import pathlib, sys
src, inst = (pathlib.Path(a).resolve() for a in sys.argv[1:3])
def tree(p):
    return {f.relative_to(p).as_posix(): f.read_bytes()
            for f in p.rglob('*') if f.is_file() and '__pycache__' not in f.parts}
s, i = tree(src), tree(inst)
assert set(s) == set(i), (sorted(set(s) - set(i)), sorted(set(i) - set(s)))
bad = sorted(k for k in s if s[k] != i[k])
assert not bad, bad
print(f"ui-html census: {len(s)} files byte-identical (checkout vs installed wheel)")
```

run as `python -I -c <block> <checkout>/packages/ui-html/src/benchweave_ui_html <installed pkg dir>` — the checkout-side path carries the member segment `packages/ui-html/` (a dropped segment fails loud at P2-local, not quietly against the wrong tree); the installed dir is resolved the same way the landed step already resolves the import. The `__pycache__` filter is needed on BOTH sides: the smoke's own imports create it installed-side, and hatchling's built-in rules keep it out of the wheel (measured, §1). `diff -r` was rejected for portability (BSD `diff` on the macos leg has no `--exclude`). Beside the census: `from benchweave_ui_html.assets import verify_vendored_assets; assert verify_vendored_assets() == []` — the shipped inventory verifier run from the installed location (its `ASSETS_DIR` is `Path(__file__).parent / "assets"`, so it verifies the WHEEL's bytes, and its exhaustive-census + byte-pin arms come free — `assets.py` is already shipped and tested).

**Why this shape:** the expected set IS the source tree — no second enumeration to drift. The in-tree pins (`test_templates_packaged.py`'s frozensets, the inventory census) stay the source-tree authority; this check proves the DISTRIBUTION carries them byte-identical. Placement: **both** package.yml (every push/PR — catches packaging-config drift, e.g. a future hatch `exclude` or a moved template, at PR time) and the publish smoke (re-proven at the tag). Not a new pytest file: a pytest arm cannot see a wheel without building one inside pytest (slow, needs the build env) — the CI step is the right home.

**Source-side asymmetry, named:** the census assumes a clean checkout. An ignore-filtered stray on the source side (a Finder-touched `.DS_Store`, any gitignored leftover) reds the census BY DESIGN — and the response is clean-the-checkout or extend the filter, NEVER the conscious-exclusion packaging fork of the KILL rule. Hatchling excludes gitignored files from the wheel (measured, §1), so the installed side cannot carry what the checkout's ignore rules exclude; the asymmetry is real and one-directional by construction.

**What the census does NOT catch (G4):** anything about files the sdist carries that the wheel legitimately lacks (irrelevant to consumers); PyPI-side substitution AFTER publish (the verify job's digest read-back covers that window); the completeness of files added to the source tree but never registered in any pin — a NEW template file lands in the census's expected set automatically (source == installed), so the census proves transport, not authorship: a template nobody renders still ships. That authorship half is the in-tree tests' job (`test_templates_packaged` pins the exact set). Both halves named.
