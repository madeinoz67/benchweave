# Issue #79 — Machine-written, CI-pinned OTDP validation report (design)

**Date:** 2026-09-20 · **Issue:** [#79](https://github.com/madeinoz67/benchweave/issues/79)
**Status:** design, pre-build · **Verdict:** BUILD — the report is hand-maintained today; verified below.
**Baseline:** `main` at `79fb7b6`.

## 1. Root cause (established, not assumed)

`standards/otdp/0.2.0/validation-report.md` is a hand-transcribed rendering of the output of
`scripts/architecture/check_devices.py`, with three structural gaps that make a stale or
fabricated report pass silently:

1. **No writer.** `check_devices.py` accumulates `checks` (module level, `check_devices.py:29`)
   and its `__main__` block only prints `{passed}/{total} checks passed`
   (`check_devices.py` tail); it writes nothing. The report's 569 `- PASS:` lines were
   transcribed by hand. (Live re-verification on `79fb7b6`: `569/569 checks passed`, exit 0,
   ~1.5 s wall — the number is honest today; the mechanism is the gap, exactly as the issue says.)
2. **No pin.** The report is a tier-2 standards prose companion (`docs/doc-taxonomy.md` row 2) —
   it has **no row in `standards/corpus-manifest.json`** (text search for `validation-report`
   returns zero manifest hits), so no digest gate covers it. Proven by history: `a245090`
   edited the 0.2.0 report in place post-bump, and `90f9af1` edited plugin-ui 0.1.1's report
   the same way — both landed gate-free. Editing prose inside an active version dir is a
   no-bump change class by `standards/GOVERNANCE.md` ("Prose is not digest-pinned"), which is
   correct for prose and is exactly the hole for a report that carries a measured count.
3. **No consumer check.** The count `569` also lives in `docs/README.md:31`
   ("569 passing document/schema checks"); nothing relates either surface to a live run.

`check_devices.py` itself already runs in CI — `tests/contracts/test_architecture.py` executes
all seven suites via `runpy.run_path` inside the `gates` job's `pytest -q` — so the live run
the report should be pinned to is available for free. The gap is purely that its output is
never compared to the committed artifact.

A06 framing: a hand-transcribed count next to the corpus it claims to verify is an assertion.
This increment makes it evidence.

## 2. The mechanism — write + pin (both halves)

Two coordinated pieces, mirroring the proven `benchweave.standards matrix` render/check pair:

**Writer (author-side, explicit).** `check_devices.py` gains a pure renderer
`render_report(checks) -> str` and an argv-gated `--write-report` branch in its `__main__`
block that writes `OUT / "validation-report.md"` (`OUT = STANDARDS / "otdp/0.2.0"`, already a
script global). The writer **refuses to write when any check fails** (exit non-zero naming the
failures) — it must never be able to fabricate a green artifact from a red run. Prose (title,
coverage paragraph, `**Limit:**` paragraph) becomes string constants in the script, carrying
today's bytes verbatim. The rendered file gains a first-line generated marker, per the matrix
precedent:

```
<!-- Generated by scripts/architecture/check_devices.py --write-report — regenerate on check changes; do not hand-edit. -->
```

**Rendering is canonical over the checks SET, not the execution order**: the `## Checks` list
is emitted sorted lexicographically by check name. Reason: check order today is partly
filesystem-dependent (`schemas` dict is built from `OUT.glob("*.schema.json")` at
`check_devices.py:54`, and glob order is directory-entry order — the committed report's
meta-schema ordering is the authoring machine's, not a portable order). Sorting makes the pin
a function of the check set only, immune to platform glob order. First writer run therefore
reorders the committed file's check lines (content-identical permutation) and inserts the
marker; the diff review confirms permutation + marker only.

**Pin (CI-side, read-only).** `tests/contracts/test_architecture.py` gains
`report_failures(docs, standards) -> list[str]` (mirroring `check_matrix`): run the devices
suite, render, compare bytes to the committed report; on mismatch return one failure naming
the file and the remediation command. Two tests use it:

- `test_validation_report_matches_live_run` — against the real tree; also asserts the
  `docs/README.md` row linking this report carries the live count (locate the row by href,
  take the first integer; prose defers to the machine number).
- one tamper case — copy `docs/` + `standards/` to tmp (the `test_validation_is_read_only`
  pattern), flip one committed `- PASS:` to `- FAIL:` (and a second parametrized case: bump
  the headline count by one), assert `report_failures` reports the drift.

**Why CI compares and never writes** — `docs/architecture-validation.md` already states the
doctrine: "Keep validators read-only; CI must report drift rather than regenerate expected
files to make the check pass." The argv gate lives inside `__main__`, and the pytest harness
cannot reach it: `runpy.run_path`'s default `run_name` is `"<run_path>"`, not `"__main__"`,
so the harness executes the module body (accumulating `CHECKS`) but never the `__main__`
block — the existing `test_validation_is_read_only` byte-snapshot additionally pins that no
suite writes. The writer is structurally author-only, not policy-only.

## 3. Precedent (extended, not invented)

- `src/benchweave/standards/matrix.py` — `render_matrix` (pure) + `check_matrix`
  (committed-vs-fresh, failure names the regen command) + `GENERATED_MARKER` in the artifact,
  wired to CI via `make check-sdk-standards`. This design transplants that pattern to a
  scripts-architecture validator, whose CI lane is the pytest suite rather than the Makefile.
- `tests/contracts/test_architecture.py::run_checks` — the runpy harness with
  `init_globals={"DOCS", "STANDARDS"}` and mutation-in-tmp-copies
  (`test_contract_regressions_are_detected`) is the reuse point for both the pin and the
  tamper control.
- Why not a new architecture: a Makefile/CI workflow change would add a lane for something
  the existing `gates` pytest run already executes; a package-side writer would move the
  renderer away from the checks that feed it (two renderers would be the new drift surface).

## 6. Invariant, drift and tier impact

- **New invariant CON-11** as above; no existing CTL/STO/CON/REG invariant is touched. The
  architecture-suite read-only pin (`test_validation_is_read_only`) is explicitly preserved.
- **Tier**: no on-disk machine format or schema changes; the regenerated artifact is prose
  (unpinned by design, now writer-pinned). Not a Tier 3 (schema/format) change. No standards
  version train.
- **Surfaces moved**: script, regenerated report, pin tests, `docs/architecture-validation.md`,
  `docs/internal/drift-and-obligations.md`, `docs/internal/invariants.md`,
  `standards/GOVERNANCE.md`. `docs/README.md` needs no edit (count unchanged at 569) but is
  now guarded. Docs-site assembly is content-agnostic for this file (ranks by filename).
- **CI cost**: ~4–5 s in `gates`; no new job, lane or workflow.

## 7. Pre-committed acceptance rule (committed before any effect measurement)

The only number looked at so far is the status quo (569/569 live, §1) — it is not the effect
measurement. The rule:

**Metric** — byte-equality between the committed `standards/otdp/0.2.0/validation-report.md`
and a fresh `render_report` of a live devices-suite run; plus the two designed failure modes
of that equality.

1. **RED (ships nothing until seen)**: on unmodified `main`, before the writer lands, the new
   pin test FAILS against the committed hand-written report (line order + absent marker make
   the bytes differ). Observed failure = the test bites. The tamper cases are then trivially
   green-on-red (they mutate a copy and expect the failure).
2. **GREEN**: after the writer + regeneration, `pytest tests/contracts/test_architecture.py`
   passes locally AND in CI (CI = the cross-platform determinism check: ubuntu render equals
   the macOS-authored bytes — that is the ongoing instrument, not a one-off claim). Writer
   idempotence: run `--write-report` twice, second run is a zero diff.
3. **Ship direction**: RED observed → GREEN local + CI, diff of the regenerated report shown
   in the PR to be permutation + marker only (headline and count unchanged).
4. **Kill directions**:
   - Sorted rendering still yields platform-dependent bytes (CI render ≠ local) → the
     byte-pin mechanism is WRONG; kill, fall back to a count+membership assertion, and record
     the honest negative in this directory.
   - The regenerated diff cannot be made permutation-only (renderer forces content changes
     beyond order + marker) → template diverged from committed prose; STOP and reconcile —
     do not "fix" the report's prose to match a renderer.
   - Added `gates` time exceeds ~10 s → share one suite execution via a session fixture
     (mechanical adjustment, not a kill).
5. **Underpowered criterion**: determinism evidence is 2 platforms × (1 + reruns) renders. If
   both agree, that is evidence, not proof — a future platform disagreement MUST surface as a
   pin failure with a diff (loud), which is the designed behavior; if it ever surfaced as a
   flake instead, the pin is underpowered and gets replaced by the count+membership fallback.

## 8. RED→GREEN commit slicing (one slice per commit)

1. Commit the design record (this file) on the working branch.
2. Pin tests only (`report_failures` + live pin + tamper cases; `load_suite` refactor) — RED
   on `main`'s tree: collected-count shown, `test_validation_report_matches_live_run` fails
   on byte mismatch.
3. Writer + regenerated report + all doc surfaces — GREEN locally; push; `gates` green closes
   the rule.

## 9. Top risks and falsifiers

| Risk | Falsifier |
|---|---|
| Check-name duplicates or unstable names make sorted rendering still non-deterministic | RED phase: render twice locally in one process and across processes; any diff kills the byte-pin (rule 7.4). |
| The pin hardcodes `otdp/0.2.0` and goes stale-silent after the next bump | It cannot go stale silently: on a bump that copies the report, the pin FAILS (live render points at the new dir's corpus via the script's `OUT`), naming the regen command; D2 removes the hardcode when that fires. |
| The writer is used to launder a failing run | Structural: writer refuses on any failure; CI path cannot write at all (run_name + read-only pin). |
| Prose numbers inside the template drift from reality while the count stays right | Stated residual (D3): the pin guarantees check lines and headline, not in-prose numbers; the honest-limits paragraph is review-guarded, and the guard's "does not catch" statement says so. |
| Reviewers mistake the one-time reorder for content change | Rule 7.3 requires the permutation-only diff in the PR; reviewer verifies sorted(old lines) == sorted(new lines). |
