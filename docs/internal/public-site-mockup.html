The plan

Four commitments from the architecture, not four feature bullets.

Connect

Instruments and devices under test through reusable plugins and typed device profiles.

Share

Profiles and implementations through a central registry, with local admission and offline execution.

Coordinate

Bounded test procedures with explicit ownership, measurement evidence, and verified safe endings.

Expose

A consistent REST and MCP interface for applications and coding agents.

Standards

The versioned contracts that everything else is built against — treated as agreements, not informal notes. Each one is independently versioned.

Device developer guide

Device creation, gateway hosting, and shared packages — for human and AI authors.

Before you start

Independent plugin repositories and releases are the preferred authoring path. Device plugins integrate existing instruments or custom hardware.

benchweave-sdk new plugins/acme/model100 --package benchweave_acme_model100

Replace acme/model100 with your manufacturer/device name. The generated project contains src/ and tests/.

SDK

The plugin developer SDK lives in its own repository with its own release cycle.

benchweave-sdk

Build an external device plugin without importing gateway internals. Python 3.13+ · SDK 0.1.0 · OTDP 0.3.0 baseline.

pip install benchweave-sdk
uv tool install benchweave-sdk
brew install madeinoz67/tap/benchweave-sdk

Five steps

  1. Install the SDK from PyPI.
  2. Run benchweave-sdk new plugins/<manufacturer>/<device>.
  3. Replace the synthetic protocol with verified device behaviour.
  4. Run tests, then benchweave-sdk check against the descriptor.
  5. Build, prepare registry metadata, and get evidence reviewed before release.
