# ADR 0094 — Rigol DM858 integration

Status: Accepted

## Context
The DM858 integration must provide the OTDP DMM class actions configure and measure. BenchWeave's device developer guide places class actions in adapter mode. The owner approved the AC-2 correction and publication on 2026-11-28 in madeinoz67/benchweave#94, comment 7235047044.

## Decision
Use a scoped SCPI adapter. Qualify USBTMC first and expose retained one-shot readings. LAN and streaming are outside the first increment. Declare only verified firmware and function, range and aperture combinations. The adapter validates the declared constraints before I/O. A malformed or overload response must not produce a valid measurement.

## Options
A declarative binding supports elementary reads but cannot supply the required DMM actions. Qualifying USBTMC and LAN together increases bench work without changing the first increment's measurement contract.

## Implementation and verification
1. Package the descriptor against the pinned DMM profile with the measure role, configure and measure actions, and self-contained input constraints. Verify descriptor validation and class-reference resolution.
2. Bind identification, configuration and one-shot measurement over the scoped transport. Revised AC-2 uses a mock SCPI transport through the adapter to prove identity and DC voltage in volts with measured truth basis. Prove undeclared inputs are refused before I/O and invalid responses never create valid readings.
3. Qualify the installed firmware and supported voltage, current, resistance, continuity and diode combinations on the meter. Record the supported range, resolution and overload behaviour before declaring support. Run the plugin lint, type and test gates.

## Consequences and rollback
Preserve the host transport and retained capture contracts. No new profile or stream contract is required. If qualification fails, withhold the affected support claims. Withdraw plugin registration if release verification fails.
